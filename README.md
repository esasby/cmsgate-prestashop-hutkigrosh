# Модуль оплаты ХуткiГрош (ЕРИП) для PrestaShop

Модуль обеспечивает взаимодействие интернет-магазина на базе **PrestaShop** с платёжным сервисом [ХуткiГрош](https://hutkigrosh.by): выставление счетов в ЕРИП (АИС "Расчет"), оплата картой (WebPay), QR-код, автоматическое обновление статусов заказов после оплаты.

## Поддерживаемые версии

Поддерживаются одновременно две версии модуля:

| | [HutkiGrosh API v3](#настройка-hutkigrosh-api-v3) (рекомендуется) | [HutkiGrosh](#настройка-hutkigrosh-предыдущее-поколение) (предыдущее поколение) |
|---|---|---|
| Текущая версия | 3.0.1 (`ps_hutkigrosh_apiv3.zip`) | 1.13.1 (`ps_hutkigrosh.zip`) |
| API | актуальное поколение (REST API v3) | предыдущее поколение API |
| Подключение | API-токен, выбор услуги из списка | логин/пароль, ЕРИП ID вручную |
| Тестовая система | api-sandbox.hgrosh.by | trial.hgrosh.by |
| Кому подходит | новым магазинам и тем, кто переходит на API v3 | действующим магазинам, работает как раньше |

> Сервис ХуткiГрош сейчас поддерживает все поколения API параллельно.

Следите за анонсами о сроках отключения старого API и переходите на API v3 заранее (порядок перехода описан в разделе "[Одновременная работа и переход на API v3](#одновременная-работа-и-переход-на-api-v3)").

## Скачать

Для каждой версии модуля используется свой файл сборки (.zip):

| PrestaShop | Сборка API v3 (рекомендуется) | Сборка предыдущего поколения |
|---|---|---|
| 1.7 | [ps_hutkigrosh_apiv3.zip](https://github.com/esasby/cmsgate-prestashop-hutkigrosh/blob/master/ps_hutkigrosh_apiv3.zip) (проверено на 1.7.8) | [ps_hutkigrosh.zip](https://github.com/esasby/cmsgate-prestashop-hutkigrosh/blob/master/ps_hutkigrosh.zip) (проверено на 1.7.4, 1.7.6) |

Отдельная сборка API v3 обусловлена сменой поколения API сервиса, а не изменениями PrestaShop: внутри одной версии CMS обе сборки отличаются только поколением API.

## Требования

- Сборка API v3: PHP 7.1 и выше (минимальная версия для PrestaShop 1.7.8, на котором проверена сборка), расширение [cURL](https://www.php.net/manual/ru/book.curl.php)
- Сборка предыдущего поколения: PHP 5.6 и выше (версии PHP ограничены самим PrestaShop: для 1.7.4 - 1.7.6 поддерживаются PHP 5.6 - 7.2), расширение [cURL](https://www.php.net/manual/ru/book.curl.php)

## Установка (одинакова для обеих версий модуля)

**PrestaShop 1.7:**

1. Создайте резервную копию магазина и базы данных.
1. Скачайте архив нужной сборки (раздел "Скачать").
1. В административной части PrestaShop выберите `Модули > Менеджер модулей > Загрузить модуль`, укажите скачанный архив и дождитесь завершения установки.
1. В списке модулей (категория `Прочее` (Other)) напротив модуля **ХуткиГрош (API v3)** (сборка API v3) или **ХуткiГрош** (сборка предыдущего поколения) нажмите "Настроить" и заполните параметры (см. разделы настройки ниже).
1. Сохраните изменения: после этого на странице выбора способа оплаты клиенту будут доступны два новых способа (создаются модулем автоматически):
   * **Через систему «Расчет» (ЕРИП)** - выставление счёта в ЕРИП, содержит основные настройки модуля;
   * **Оплата картой** - использует общие настройки с первым способом и перенаправляет клиента к оплате счёта картой (WebPay).

## Настройка HutkiGrosh API v3

### Шаг 1. Получите API-токен

В бизнес-аккаунте ХуткiГрош откройте **Настройки > Интеграция ПУ** (раздел доступен ролям "Владелец ПУ" и "Администратор ПУ"). Используйте токен с доступом к информации о ПУ и созданию/редактированию счетов.

### Шаг 2. Подключите магазин

1. В настройках модуля вставьте токен в поле **API Токен**.
1. Нажмите кнопку "Актуализировать" (рядом с полем **API Токен**), модуль загрузит из ХуткiГрош справочники для полей **Услуга**, **Розничная торговая точка**, **Кассовое место** (загруженные значения сохраняются в настройках и восстанавливаются при открытии формы без обращения к API).
1. Выберите значения в списках и сохраните изменения.

### Шаг 3. Остальные параметры

**Основное:**
* **Sandbox**: тестовый режим работы, счета выставляются в тестовую систему `api-sandbox.hgrosh.by` с токеном тестовой системы.
* **Debug mode**: отображение деталей ошибок.
* **Использовать номер заказа**: если включен, то в ЕРИП будет выставлен счет с локальным номером заказа (orderNumber), иначе - с локальным идентификатором (orderId).
* **Путь в дереве ЕРИП**: путь, по которому клиент будет искать выставленный счёт (например, `АИС "Расчет" (ЕРИП) > Интернет-магазины/сервисы >`).
* **Срок действия счета (дней)**: как долго счёт будет доступен в ЕРИП для оплаты (от 1 до 10).

**Экран успешного заказа:**
* **Секция "Инструкция"**: пошаговая инструкция по оплате счёта в ЕРИП.
* **Секция QR-код**: оплата счёта по QR-коду через мобильное приложение банка (QR-код и ссылка на оплату запрашиваются у сервиса).
* **Секция Webpay**: кнопка оплаты счёта картой (переход на Webpay).
* **Текст успешного выставления счета**: может содержать HTML, допустимы переменные `@order_id`, `@order_number`, `@order_total`, `@order_currency`, `@order_fullname`, `@order_phone`, `@order_address`.
* **CSS файл для итогового экрана**: путь к собственному CSS-файлу оформления.

**Статусы заказов** (выбор из существующих статусов магазина, список статусов - `Параметры магазина > Настройки заказов > Статусы`):
* **Статус при выставлении счета**: какой статус установить заказу после выставления счёта в ЕРИП. Рекомендуется один из статусов "Ожидание..." (например, "Ожидание банковского перевода"), заказ ожидает оплаты.
* **Статус при успешной оплате счета**. Рекомендуется "Оплата принята" (Payment accepted), оплата получена, заказ ожидает комплектации и отправки.
* **Статус при отмене оплаты счета**. Рекомендуется "Отменено" (Canceled).
* **Статус при ошибке оплаты счета**. Рекомендуется "Ошибка платежа" (Payment error).

**Уведомления** (отправляются шлюзом ХуткiГрош):
* **Email оповещение**: письмо клиенту при успешном выставлении счёта.
* **Sms оповещение**: SMS клиенту при успешном выставлении счёта.

**Способ оплаты для клиента:**
* **Название способы оплаты**: название, отображаемое клиенту при выборе способа оплаты (по умолчанию "Через систему «Расчет» (ЕРИП)").
* **Описание способа оплаты**: подробное описание, отображаемое клиенту при выборе способа оплаты.
* **Название способы оплаты webpay**: название способа оплаты картой (по умолчанию "Оплата картой").
* **Описание способа оплаты webpay**: подробное описание способа оплаты картой.

### Обязательно: адрес обработчика уведомлений

Для автоматического обновления статуса заказа (после оплаты клиентом счёта в ЕРИП) сообщите в службу технической поддержки ХуткiГрош адрес обработчика, указав Ваш домен (для сборки API v3):

```
https://ваш-домен/module/ps_hutkigrosh_apiv3/callback
```

Если магазин расположен в подпапке или включён мультиязычный режим, адрес будет содержать соответствующие префиксы (например, `https://ваш-домен/prestashop/ru/module/ps_hutkigrosh_apiv3/callback`).

Модуль принимает уведомление GET-запросом с идентификатором счёта (`purchaseid`) в URL.

### Тестовый режим (Sandbox)

1. Получите API-токен тестовой системы (выдаётся при регистрации в ХуткiГрош).
1. Включите в настройках модуля режим **Sandbox** и настройте согласно инструкции выше.
1. Счета будут выставляться в тестовую систему `api-sandbox.hgrosh.by`.
1. Для эмуляции оплаты счёта используйте [личный кабинет](https://cabinet.hgrosh.by) (сверху-справа "Профиль пользователя" > "Тестовый режим").

Документация API v3: https://api-dev.hgrosh.by/eripservice/docs/ru/index.html

## Одновременная работа и переход на API v3

* Сборка API v3 - самостоятельный модуль `ps_hutkigrosh_apiv3`: он устанавливается независимо от предыдущего модуля `ps_hutkigrosh`, записи в списке модулей и настройки у них разные. Оба модуля могут работать одновременно, заказы и данные магазина не затрагиваются.
* Пока включены оба модуля, клиенту доступны обе пары способов оплаты ("Через систему «Расчет» (ЕРИП)" и "Оплата картой" от каждого модуля): после завершения проверки отключите предыдущий модуль.
* Адрес обработчика уведомлений у сборки API v3 другой (`/module/ps_hutkigrosh_apiv3/callback`): сообщите новый адрес в службу технической поддержки ХуткiГрош.
* Настройки предыдущего поколения не переносятся автоматически: поля подключения заполняются заново, вместо "Логин/Пароль/ЕРИП ID/Код услуги" указывается "API Токен" и справочники "Услуга", "Розничная торговая точка", "Кассовое место".

Рекомендуемый порядок перехода:

1. Создайте резервную копию магазина и базы данных.
1. Получите API-токен тестовой системы (см. "Настройка HutkiGrosh API v3", шаг 1).
1. Установите сборку API v3 (порядок установки см. в разделе "Установка").
1. В настройках модуля вставьте токен в поле "API Токен", нажмите "Актуализировать" и выберите значения в списках "Услуга", "Розничная торговая точка", "Кассовое место".
1. Включите режим Sandbox и проверьте выставление и оплату счёта (эмуляция оплаты в личном кабинете, см. "Тестовый режим").
1. Выключите Sandbox и вставьте токен, выданный для рабочей системы, в поле "API Токен", нажмите "Актуализировать" и выберите значения в списках "Услуга", "Розничная торговая точка", "Кассовое место": счета будут выставляться в рабочую систему `api.hgrosh.by`.
1. Проверьте обработчик уведомлений: статус заказа в магазине должен измениться после оплаты счёта. После этого сообщите в поддержку ХуткiГрош адрес обработчика API v3 и отключите предыдущий модуль.

## Логи

Модуль ведет лог файл по пути:

* сборка API v3: `<корень_сайта>/modules/ps_hutkigrosh_apiv3/vendor/esas/cmsgate-core/logs/cmsgate.log`
* сборка предыдущего поколения: `<корень_сайта>/modules/ps_hutkigrosh/vendor/esas/cmsgate-core/logs/cmsgate.log`

Для обеспечения **безопасности** необходимо убедиться, что в настройках http-сервера включена директива `AllowOverride All` для корневой папки.

По вопросам подключения и работы сервиса обращайтесь в службу технической поддержки [ХуткiГрош](https://hutkigrosh.by).
